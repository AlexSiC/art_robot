# Как посмотреть воспроизведение рисунка в ROBOGUIDE

Пошаговая инструкция: загрузить сгенерированную программу `svg2fanuc` в ROBOGUIDE
и увидеть, как коллаборативный робот FANUC «рисует» фотографию из
`png2svg/examples/output_photo_2026-08-28/`.

> Это **кинематическая симуляция**. Досягаемость, сингулярности и коллизии здесь
> — только ориентир. Итоговая проверка — на вашей реальной ячейке.

---

## 0. Что загружать

Все файлы уже лежат в репозитории:

```
svg2fanuc/examples/photo_2026-08-28/
├── ART00001.LS      ← основная программа (122 движения, ~48 с цикл)
├── CELL_IN.LS        ← заглушка «вход в зону» (заменяется на реальную)
├── CELL_OUT.LS       ← заглушка «выход из зоны»
├── preview.svg       ← как ДОЛЖЕН выглядеть результат (для сверки)
├── trajectory.json   ← нейтральный план движений (справочно)
└── report.json       ← метрики и проверки
```

Профиль, которым это сгенерировано: `svg2fanuc/profiles/roboguide_cr7ial.yaml`.
Холст 450 × 340 мм, поле 15 мм, рисунок вписан в область 32…417 × 15…325 мм.

Если нужен другой размер холста / другой робот — правьте YAML и повторите:

```bash
cd svg2fanuc
svg2fanuc generate ../png2svg/examples/output_photo_2026-08-28/clean.svg \
  --profile profiles/roboguide_cr7ial.yaml --out examples/photo_2026-08-28 --force
```

## 1. Модель робота

**Берите `CR-7iA/L`.**

| Параметр | Значение |
|---|---|
| Тип | коллаборативный, 6 осей |
| Полезная нагрузка | 7 кг |
| Вылет | 911 мм |
| Контроллер | R-30iB Plus |
| Появился | 2016 г. — есть в любой версии ROBOGUIDE начиная с ~2017, включая сборки 2020 г. |

Почему не CRX: белые CRX-10iA/L и т.д. вышли в конце 2019 г. и появляются в
ROBOGUIDE только с V9 Rev D и плагина CRX. Если ваш ROBOGUIDE старше — их не будет
в списке. `CR-7iA/L` есть везде.

**Альтернативы**, если хотите:

- `CR-4iA` — маленький (4 кг, вылет 550 мм). Тогда уменьшите холст в профиле до
  ~250 × 190 мм и перегенерируйте.
- `CR-15iA` — крупнее (15 кг, вылет 1441 мм), можно холст побольше.
- `CRX-10iA/L` — тот самый белый кобот, если ваш ROBOGUIDE его показывает.

Модель влияет только на симуляцию — сам `.LS` от модели не зависит (в нём
декартовы координаты, кинематику решает контроллер).

## 2. Создать ячейку

1. **File → New Cell** (или мастер «New» при запуске).
2. Имя ячейки — например `art_robot_demo`.
3. Процесс — **HandlingPRO**. Next.
4. **Create a new robot with the default HandlingPRO config**. Next.
5. Версия ПО виртуального контроллера — любая **V9.xx** (например V9.30). Next.
6. Application / Tooling — оставить по умолчанию («Basic» / «GIC Handling»). Next.
7. **Group 1 Robot Model** — в списке найти и выбрать **`CR-7iA/L`**
   (раздел Collaborative / CR series). Next.
8. Additional Motion Groups — нет. Next.
9. Additional Options — оставить по умолчанию.
   *(По желанию можно отметить `ASCII Upload (R632)` — тогда контроллер принимает
   `.LS` напрямую; для ROBOGUIDE это не обязательно.)* Next.
10. **Finish**. Дождаться сборки ячейки.

## 3. Инструмент — Tool Frame 1 (кисть)

На виртуальном пульте (иконка Teach Pendant):

1. **MENU → 6 SETUP → F1 [TYPE] → Frames**.
2. **F3 [OTHER] → Tool Frame**.
3. Курсор на строку `1`, **F2 DETAIL**.
4. Ввести (метод Direct Entry):
   - Comment: `BRUSH`
   - X = `0`, Y = `0`, **Z = `150`** (вылет кисти от фланца, мм — поставьте свой),
   - W = `0`, P = `0`, R = `0`.
5. **PREV**, курсор на `1`, **F5 SETIND**, ввести `1` — Tool Frame 1 активен.

---

## 4. Холст — User Frame 1

Программа рисует в системе координат `UFRAME 1`. Её ось **Z смотрит вверх**,
начало — в углу холста, X — вдоль ширины (450 мм), Y — вдоль высоты (340 мм).
Кисть (ориентация W180 P0 R0) при этом смотрит вертикально вниз.

### Быстрый способ (Direct Entry)

1. **MENU → SETUP → Frames → F3 [OTHER] → User Frame**.
2. Курсор на `1`, **F2 DETAIL → F2 [METHOD] → Direct Entry**.
3. Ввести (относительно World) стартовые значения:
   - X = `380`, Y = `-210`, Z = `-100`,
   - W = `0`, P = `0`, R = `0`.
4. **PREV**, курсор на `1`, **F5 SETIND**, ввести `1`.

Это ставит холст ~380 мм перед основанием робота, горизонтально. Проверка
досягаемости — в шаге 6; если точки «не достаёт», подвиньте фрейм ближе/ниже.

### Аккуратный способ (со «столом»)

1. В **Cell Browser** → узел **Fixtures** → правый клик → **Add Fixture → Box**.
2. Размер, например, `500 × 400 × 700` мм (столешница-подставка).
3. Разместить перед роботом: в свойствах фикстуры Location X ≈ `600`, Y = `0`,
   Z = `0` (верх стола окажется на Z ≈ 700, при роботе на своей стойке —
   подберите так, чтобы столешница была в зоне досягаемости).
4. Задать `UFRAME 1` по верхней грани стола 3-точечным методом
   (**F2 [METHOD] → Three Point**): начало, точку по +X, точку по +Y.

## 5. Загрузить программы

Порядок важен: сначала заглушки, потом основная (иначе `ART00001` не найдёт
`CALL CELL_IN` / `CALL CELL_OUT` при компиляции).

1. В **Cell Browser** раскрыть робота → узел **Programs** (или **TPPs**).
2. Правый клик → **Load Program…** → выбрать `CELL_IN.LS` → OK.
3. Так же загрузить `CELL_OUT.LS`.
4. Так же загрузить `ART00001.LS`.

Если ROBOGUIDE ругается на трансляцию — проверьте, что заданы и активны
`UFRAME 1` и `UTOOL 1`, и что обе заглушки уже загружены.

## 6. Запуск и просмотр «как рисует»

### Включить след TCP (это и есть «увидеть рисунок»)

- Лента **Robot → Trace** (или правый клик по роботу → **Trace**).
- В настройках трассы: цвет линии, «рисовать только при движении по траектории»
  можно оставить как есть. Включить трассу (галочка/тумблер On).

### Выбрать и запустить программу

1. На пульте: **SELECT** → курсор на `ART00001` → **ENTER**.
2. Панель запуска ROBOGUIDE (кнопки как у видеомагнитофона внизу/сбоку) →
   **Play / Cycle Start**.
3. Робот проходит траекторию; за кистью тянется линия трассы.

### Что вы увидите и с чем сверить

- Линия трассы должна повторить `preview.svg` из папки примера.
- В панели запуска — **время цикла** (ожидаемо ~48 с при заданных скоростях).
- Красным пунктиром в `preview.svg` показаны холостые перелёты (кисть поднята
  на `z_clear` = 12 мм); в ROBOGUIDE они идут на высоте 12 мм над холстом.

## 7. Типовые проблемы

| Симптом | Причина / что делать |
|---|---|
| Позиции жёлтые, «unreachable» | Холст далеко/высоко. Подвиньте `UFRAME 1` ближе к роботу (уменьшите X), измените Z. Либо возьмите холст меньше в профиле и перегенерируйте. |
| Alarm «singularity» или «wrist» | Кисть строго вертикальна (P = 0) у края зоны. В профиле `orientation_wpr_deg` поставьте `[180, 15, 0]` (лёгкий наклон) и перегенерируйте. |
| Alarm «joint limit» на J1/J4/J6 | Робот «выкручивается» на краю холста. Поверните `UFRAME 1` (параметр R) или сместите холст к центру рабочей зоны. |
| Кисть «сталкивается» со столом | `z_draw` = 0 = ровно плоскость `UFRAME 1`. Опустите верх фикстуры на 1 мм ниже начала фрейма, либо отключите проверку коллизий для стола. |
| Робот стартует «из ниоткуда» | `CELL_IN` — заглушка (только комментарии). Перед запуском сместите (jog) робота в точку над центром холста, либо впишите в `CELL_IN` реальное движение подхода. |

## 8. Дальше — к реальному роботу

1. Заполнить свой профиль ячейки (модель, контроллер, версия ПО, реальные
   `UFRAME`/`UTOOL`, проверенный `CONFIG`, размеры холста, `z_draw`/`z_clear`,
   реальные `CELL_IN`/`CELL_OUT`).
2. `svg2fanuc generate … --production` (требует профиль без `TBD`).
3. `svg2fanuc compile …` — `MakeTP` собирает `.LS` → `.TP` под `robot.ini`
   вашей виртуальной ячейки.
4. Прогнать в ROBOGUIDE на вашей реальной геометрии ячейки: досягаемость,
   сингулярности, коллизии, время цикла.
5. Загрузка на контроллер и запуск — отдельным диспетчером, после подтверждения
   оператора. `svg2fanuc` робот не запускает.

> **GENERATED ≠ SAFE TO RUN.**
